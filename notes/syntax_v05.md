# Tin v0.5 syntax (decided 2026-10-01)

Theme: **Go, plus what matters made visible.** Tin keeps Go's syntax so models write it
fluently, and adds a small set of features that show, where they happen, what can fail
(`!T`, `try`, `catch`, `fail`), what gets modified (call-site `mut`) and every case of a
sum type (`enum` + exhaustive `switch`). Every addition lowers onto what the compiler
already does, except enums and `f32`.

Decisions from review: Go-style names (capitalized = exported), keep `++`/`--` and all of
Go's `for` forms. Everything else below was decided for Go familiarity and one way to write
each thing.

Status: **keep** (unchanged), **new** (syntax only), **new+** (new meaning in the checker
or code generator).

---

## 1. Files, packages, imports (keep)

```tin
package geo

import "say"
import "./shapes"
```

- **Exports (new+)**: Go's rule. A capitalized name (`Area`, `Point`, `MaxConns`) is
  visible to other packages; a lower-case one is private to its package. Today every name
  is visible; the compiler starts enforcing this, and the stdlib already follows it.
- Struct fields follow the same rule for other packages. `argo` (JSON) is generated by the
  compiler, so it reads every field, and the JSON name is the field name as written.

## 2. Bindings (keep)

```tin
x := 5
var buf []u8
var n i64 = 3
n++
const MaxConns = 4096
```

## 3. Types

| type | example | status |
|---|---|---|
| integers | `i8 i16 i32 i64 u8 u16 u32 u64` | keep |
| floats | `f64`, **`f32`** | `f32` new+ |
| bool, string | `bool`, `str` | keep |
| slice, array | `[]i64`, `[4]u8` | keep |
| map | `map[str]i64` | keep (see §9 for new key types) |
| optional | `?User` | keep |
| function | `func(i64) str`, `func(Req, mut Out)` | keep |
| fault | `fault` | keep |
| result | **`!T`**: `T` or a fault; **`!`** alone: nothing or a fault | new |

### Enums with data (new+)

```tin
type Shape enum {
    Circle(r f64)
    Rect(w f64, h f64)
    Empty
}

type Color enum { Red, Green, Blue }

s := Shape.Circle(2.0)
```

- A value holds one variant at a time. Variants follow the export rule like any name.
- An enum is a value (a tag word plus the largest payload), and `==` compares tag and
  payload by value (structs keep `==` as identity).

## 4. Functions

```tin
func Area(s Shape) f64 { ... }
func PortFrom(text str) !i64 { ... }          // may fail
func Flush(w mut Writer) ! { ... }            // may fail, returns nothing
func Split(s str) (str, str) { ... }          // keep: several results
func Parse(s str) !(str, i64) { ... }         // several results, may fail

func (p Point) Len() f64 { ... }
func (b mut Buf) Add(x u8) { ... }
```

- `!T` replaces writing `(T, fault)`: one way. The result is still a value plus a fault
  underneath, so the generated code is the same.
- Parameters are read-only unless `mut` (keep); `mut` is part of a function's type.
- **Call-site `mut` (new)**: an argument for a `mut` parameter is written `mut x`, as in
  `Put(mut box, item)`. The compiler requires it, and rejects it on a non-mut parameter.
  Method receivers are exempt (`b.Add(1)`).
- Generics (keep): `func Max[T i64 | f64](a T, b T) T`.

## 5. Errors

```tin
func PortFrom(text str) !i64 {
    n := try mint.Int(text)                   // keep: return the fault upward
    if n < 1 || n > 65535 {
        fail "port {n} out of range"          // new: return a fault
    }
    return n
}

port := PortFrom(env) catch _ { 8080 }        // new: handle in place, gives a value
cfg := Load(path) catch err {                 // or leave
    say.Line("config:", err)
    return
}
try Save(mut db, row)                         // a call that can only fail
```

- A `!T` result must go through `try` or `catch`: ignoring one is a compile error (keep).
- A `catch` block either produces a `T` or leaves (`return`, `break`, `continue`, `fail`,
  `panic`).

## 6. Optionals (keep)

```tin
u := Find(7)              // ?User
if u == nil {
    return
}
say.Line(u.Name)          // narrowed to User
```

## 7. Control flow (keep, plus exhaustive enum switch)

```tin
for i := 0; i < n; i++ { }
for i, x := range xs { }
for k, v := range m { }
for i := range 10 { }     // new: range over an integer, as in Go 1.22
for ok { }
for { }

switch code {             // keep: values, several per case, no fallthrough
case 200, 204:
    Ok()
case 404:
    Missing()
default:
    Other()
}

switch s {                // new+: enum variants bind their data
case Circle(r):
    a = 3.14159 * r * r
case Rect(w, h):
    a = w * h
case Empty:
    a = 0
}

defer w.Close()
```

- A `switch` on an enum must list every variant or have `default`; otherwise it is a
  compile error naming the missing variants.
- Labels for nested loops (keep Go's): `Outer: for ... { continue Outer }`.

## 8. Strings

```tin
msg := "user {u.Name} has {n} items"          // new: interpolation
row := "{price:.2} {id:x} {name:-12}"         // format: precision, hex, width/align
raw := `no {interpolation} or \escapes here`  // keep: raw string
"{{" and "}}"                                 // literal braces
```

- Interpolation compiles into the existing formatting code: no runtime parsing.
- **SQL and Redis safety (with v0.4):** a parameter typed `query` takes an interpolated
  literal as text with bound parameters. In `db.Query("SELECT * FROM users WHERE id =
  {id}")`, `id` is sent as a parameter and never pasted into the SQL. A plain `str` is not
  a `query`, so a string built any other way is rejected at compile time.

## 9. Maps (keep, plus more key types and helpers)

Maps exist today: `map[K]V`, literals `map[str]i64{"a": 1}`, `m[k] = v`, `v := m[k]`
(the zero value when missing), `v, ok := m[k]`, `delete(m, k)`, `len(m)`, and
`for k, v := range m`. Keys today are `str` or an integer type.

New:
- **Key types (new+)**: `bool`, `f64` (by bits), enums without data, and structs whose
  fields are all valid key types, hashed and compared by value. A struct used as a key is
  copied in, so changing the original later cannot corrupt the map.
- **Order**: iteration is in insertion order. It is deterministic and needs no sorting in
  tests. Deleting keeps the order of the rest.
- **Helpers (generic, in `sift`)**: `sift.Keys(m) []K`, `sift.Values(m) []V`,
  `sift.SortedKeys(m) []K`, and for slices `sift.Map(xs, f)`, `sift.Filter(xs, f)`,
  `sift.Reduce(xs, start, f)`.

## 11. Memory, cores, trusted code (keep)


## 12. Tests (new, Go style)

```tin
// geo_test.tin
package geo

import "crucible"

func TestPortFrom(t mut crucible.T) {
    t.Equal(PortFrom("80") catch _ { 0 }, 80)
    t.Fails(PortFrom("70000"))
}

func BenchmarkArea(b mut crucible.B) {
    for i := 0; i < b.N; i++ {
        Area(Shape.Rect(2, 3))
    }
}
```

- `*_test.tin` files are compiled only by `tin test`, which runs every `TestXxx` and
  reports which passed; `tin test -bench` also runs `BenchmarkXxx`.

## A whole program

```tin
package main

import "say"
import "mint"
import "quarry"
import "argo"
import "anvil"

type Message struct {
    message str
}

type Reply enum {
    Json(body Message)
    Text(code i64, body str)
}

func route(q anvil.Req) Reply {
    switch q.Path {
    case "/json":
        return Reply.Json(Message{message: "Hello, World!"})
    case "/healthz":
        return Reply.Text(200, "ok")
    }
    return Reply.Text(404, "no route {q.Path}")
}

func handle(q anvil.Req, w mut anvil.Out) {
    switch route(q) {
    case Json(m):
        w.Json()
        argo.Put(mut w.Body, m)
    case Text(code, body):
        w.Status(code)
        w.Text(body)
    }
}

func portFrom(text str) !i64 {
    n := try mint.Int(text)
    if n < 1 || n > 65535 {
        fail "port {n} out of range"
    }
    return n
}

func main() {
    port := portFrom(quarry.Env("PORT")) catch _ { 8080 }
    say.Line("listening on {port}")
    try anvil.Serve(":{port}", handle) catch err {
        say.Line("server:", err)
    }
}
```
